## What the run taught the skills (fixed the same evening)

- **`scope.py`: twenty seed lines were one convention.** The docs write paths relative to
  the design tool's project directory. Three or more paths that resolve under one base
  are now stated once as the docs' convention, not listed as orphans; fewer say "written
  relative to `<base>`, resolves under it" instead of guessing a rename-orphan.
- **`scope.py`: a split's own template text read as citations.** The index note's
  `DOC § <heading>` and the parts' head line (the quoted form, "resolves by grep over")
  were reported as missing headings: a scanner has to know the artifacts the family
  writes. A placeholder heading is skipped; a quote ends a heading.
- **`scope.py`: three more.** A spec named by its directory was unrecognized; `.claude/`
  was not indexed, so a rule file named relative to it read as "not in the tree"; a drive
  path (a tool's install) read as an orphan. And a repository with no ancestor router now
  looks beside itself for a sibling's file (a library checked out next to the design);
  under `--root` nothing is above, so the fixtures stay deterministic.
- **`sweep.py`: the project's reports live where its rules say.** The script read
  `docs/*maintain-report*.md` only, so a repository with two reports under
  `NOTEBOOK/maintain/` (home-only, because `docs/` travels) was told it had none, and
  `--check` could not pass. Four directories are searched now; the watermark line is the
  last match, not the first (the Scope section mentions the previous one); router-named
  documents outside the set (the project's HTML documents, no budget rule) are listed as
  targets whose content test is the reader's.
- **`survey.py`: a date anywhere in a heading.** A CHANGELOG whose headings lead with the
  release name counted as "0 dated headings"; the B1 archive marker was a reader test and
  is a line; a ROADMAP digest with its dates inline in prose counted as "0 dated entries"
  and now reports the inline count, pointing at A2 past five; the `docs/` line says what
  to do when git cannot hold the directory empty.
- **`split_doc.py`: CRLF worktrees, and the prose citation form.** Both found by the SETUP
  rep reading the code: the heads and the note were written LF on CRLF bodies (the doc's
  own ending is used throughout now), and the citation scan missed `DOC.md`, "Heading" (it
  finds it now, and the dry run lists it). Corrected the same evening: the first check on
  a CRLF copy read a file-type tool's "CRLF line terminators", which it prints when one
  CRLF is present, and missed the second defect, found by the adjudication's apply (below).
- **The apply, as process.** Anchors carry their backticks; a read normalizes CRLF before
  anchoring; an apply script skips an edit already present, so a re-run after a miss is
  safe; the commit chain is all-`&&`.

## The adjudication (the same evening)

The owner adjudicated the 25 flags in that tree from four grouped questions (the holders,
the currency fixes, the placement flags, the ask's home), each with a recommended option;
every recommendation was taken. Committed there and in the sibling library; the report
gained its adjudication section, flag by flag. What it taught the skills:

- **`split_doc.py` wrote a lone carriage return into every file of a CRLF split.** The
  heading pattern captured the heading with the CRLF working copy's return, and the
  heading went into each part's title and note and the index's list: two returns per
  file, so git took all six files as binary and stored three with CRLF inside. The
  reconstruction check could not see it (the bodies were right; the generated lines were
  not). Fixed: the heading is captured without the return, and the script now asserts that
  no part and no index mixes endings when the doc did not. `harness/split-fixture/eol_check.py`
  is the check a CRLF run is held to; the repository's files were repaired in one commit
  (twelve lines with line-end returns ignored).
- **A fix in a document that travels inherits the document's audience rule.** Two fixes
  as the audit worded them would have named project-internal artifacts (spec names) in a
  document that leaves for the client, which the project's router forbids; the audit's
  action vocabulary does not know a document's audience. Caught at the apply by checking
  the travelling documents' added lines against the project's own forbidden-word list.
  Not standing yet: one instance.
- **A comment edit in a file a build tool tracks by time costs a build.** The audit
  marked its one source-comment finding so (the project's own gotcha), and the owner
  deferred it to the next build; the ask's resolution met the same cost one file over
  (a shared model's header), took the same treatment, and its contract went into the
  library's reference doc now. The skills had nothing to do: the project's router said
  it, and the rep read it.

What remains is the owner's, in that tree: the two comment edits riding its next build.
