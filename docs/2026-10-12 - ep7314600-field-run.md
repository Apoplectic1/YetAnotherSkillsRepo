## What the run taught the skills (fixed the same evening)

- **`scope.py`: twenty seed lines were one convention.** The docs write paths relative to
  the design tool's project directory. Three or more paths that resolve under one base
  are now stated once as the docs' convention, not listed as orphans; fewer say "written
  relative to `<base>`, resolves under it" instead of guessing a rename-orphan.
- **`scope.py`: a split's own template text read as citations.** The index note's
  `DOC § <heading>` and the parts' head line (the quoted form, "resolves by grep over")
  were reported as missing headings: a scanner has to know the artifacts the family
  writes. A placeholder heading is skipped; a quote ends a heading.
- **`scope.py`: three more.** A spec named by its directory was unrecognized; `.claude/`
  was not indexed, so a rule file named relative to it read as "not in the tree"; a drive
  path (a tool's install) read as an orphan. And a repository with no ancestor router now
  looks beside itself for a sibling's file (a library checked out next to the design);
  under `--root` nothing is above, so the fixtures stay deterministic.
- **`sweep.py`: the project's reports live where its rules say.** The script read
  `docs/*maintain-report*.md` only, so a repository with two reports under
  `NOTEBOOK/maintain/` (home-only, because `docs/` travels) was told it had none, and
  `--check` could not pass. Four directories are searched now; the watermark line is the
  last match, not the first (the Scope section mentions the previous one); router-named
  documents outside the set (the project's HTML documents, no budget rule) are listed as
  targets whose content test is the reader's.
- **`survey.py`: a date anywhere in a heading.** A CHANGELOG whose headings lead with the
  release name counted as "0 dated headings"; the B1 archive marker was a reader test and
  is a line; a ROADMAP digest with its dates inline in prose counted as "0 dated entries"
  and now reports the inline count, pointing at A2 past five; the `docs/` line says what
  to do when git cannot hold the directory empty.
- **`split_doc.py`: CRLF worktrees, and the prose citation form.** Both found by the SETUP
  rep reading the code: the heads and the note were written LF on CRLF bodies (the doc's
  own ending is used throughout now, verified on a CRLF copy: every file uniform), and the
  citation scan missed `DOC.md`, "Heading" (it finds it now, and the dry run lists it).
- **The apply, as process.** Anchors carry their backticks; a read normalizes CRLF before
  anchoring; an apply script skips an edit already present, so a re-run after a miss is
  safe; the commit chain is all-`&&`.
